# DevMind 数据库与向量模型

## 1. 数据库约定

- PostgreSQL：16
- pgvector：0.7.4
- 字符集：UTF-8
- 时间字段：使用 `timestamp`，统一由服务端写入
- 主键：MVP 使用 `bigserial` 或 UUID，保持全项目一致
- 向量维度：必须和实际 Embedding 模型一致，不能凭空固定

> README 中的向量维度不写死。项目初始化时读取 Embedding 模型配置，并根据实际模型创建向量字段。

## 2. knowledge_base

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | bigint | PK | 知识库 ID |
| name | varchar(100) | NOT NULL | 知识库名称 |
| description | varchar(500) | NULL | 描述 |
| status | varchar(20) | NOT NULL | ENABLED/DISABLED |
| created_by | bigint | NULL | 创建人，MVP 可为空 |
| created_time | timestamp | NOT NULL | 创建时间 |
| updated_time | timestamp | NOT NULL | 更新时间 |

索引：

```sql
UNIQUE(name)
INDEX(status)
```

## 3. document

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | bigint | PK | 文档 ID |
| knowledge_base_id | bigint | NOT NULL | 所属知识库 |
| file_name | varchar(255) | NOT NULL | 原始文件名 |
| file_type | varchar(50) | NOT NULL | md/pdf |
| file_size | bigint | NOT NULL | 字节数 |
| file_path | varchar(500) | NOT NULL | 文件路径 |
| content_hash | varchar(64) | NOT NULL | 内容 SHA-256 |
| status | varchar(20) | NOT NULL | UPLOADED/PROCESSING/COMPLETED/FAILED/DELETED |
| error_message | varchar(2000) | NULL | 失败原因 |
| created_by | bigint | NULL | 创建人 |
| created_time | timestamp | NOT NULL | 创建时间 |
| updated_time | timestamp | NOT NULL | 更新时间 |

约束：

```sql
UNIQUE(knowledge_base_id, content_hash)
INDEX(knowledge_base_id, status)
```

重复上传同一知识库中的相同内容时，优先返回已有文档；不要重复调用 Embedding。

## 4. document_chunk

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | bigint | PK | 文本块 ID |
| document_id | bigint | NOT NULL | 文档 ID |
| chunk_index | int | NOT NULL | 文档内顺序 |
| content | text | NOT NULL | 文本内容 |
| content_hash | varchar(64) | NOT NULL | 文本块哈希 |
| metadata | jsonb | NULL | 标题、页码、段落等 |
| embedding | vector(N) | NOT NULL | 向量，N 由模型决定 |
| created_time | timestamp | NOT NULL | 创建时间 |

约束：

```sql
UNIQUE(document_id, chunk_index)
INDEX(document_id)
```

向量索引在数据量达到一定规模后再创建。MVP 数据量较小时可以先使用精确搜索，避免过早调参。

## 7. 向量检索约定

基础检索逻辑：

```text
问题 -> Embedding -> 向量相似度 -> Top-K chunk
```

检索结果至少包含：

```text
chunkId
documentId
documentName
content
metadata
similarityScore
```

低于相似度阈值的结果不应直接拼进 Prompt。阈值需要通过实际文档和问题样本调整，不能凭经验写成永久固定值。

## 8. 删除和重建策略

删除文档时：

1. 先将 document 状态改为 DELETED；
2. 删除或标记对应 document_chunk；
3. 后续清理向量记录；
4. 查询时排除 DELETED 文档。

重新处理文档时：

1. 删除旧 chunk；
2. 重新解析和切分；
3. 重新生成向量；
4. 全部成功后将文档标记为 COMPLETED；
5. 失败时保留 FAILED 状态和错误原因。

不要在旧向量未清理时直接追加新向量，否则同一文档会出现重复上下文。
