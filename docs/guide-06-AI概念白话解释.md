# AI 概念白话解释

下面这些词在代码和文档里会出现，这里用大白话解释。

## 大模型（LLM）

一个经过大量文本训练出来的 AI 程序，能理解问题并生成文字。比如 OpenAI、DeepSeek、通义千问。

## Prompt

你给大模型的一段“指令和资料”。DevMind 会把问题 + 检索到的资料拼成一个 Prompt。

## Token

模型计数的单位，可以粗略理解为“一小段文字”。中文一个字通常算一到两个 Token。Token 越多，费用越高。

## API Key

调用模型的钥匙。它像密码，不能写进代码或提交到 Git。

## Embedding / 向量化

把一段文字变成一组数字，这组数字叫向量。意思相近的文字，数字也会相近。

## 向量

一组数字，例如 `[0.1, 0.2, 0.9, ...]`。向量长度由模型决定。

## 向量相似度

两个向量有多像。DevMind 用相似度给检索结果排序，分数越高越相关。

## pgvector

PostgreSQL 的一个扩展，让普通数据库能保存向量并做相似度检索。

## RAG

“先检索，再生成”。先找资料，再把资料交给大模型回答。这样回答有依据，也能给出来源。

## 文本切块（Chunk）

把长文档切成很多小块。切块让检索更快、更准，也让模型一次只读相关部分。

## Metadata / 元数据

描述数据的数据。这里主要记录文本块来自哪个标题，方便引用来源。

## Top-K

只取相似度最高的 K 个结果。默认取 5 个，最多 10 个。

## 相似度阈值

低于这个分数的结果不采用，避免把无关内容塞给模型。

## 引用来源（Reference）

回答里附带的文档出处，包含文件名、标题、文本块和相似度。

## 上下文

模型这次回答时能看到的内容。DevMind 的上下文 = 检索到的资料 + 用户问题。

## 幻觉

模型没有资料却编造答案。DevMind 通过 RAG 和“没找到就明说”的提示词来减少幻觉。

## Mock 模式

模拟模型模式，不调用真实大模型，用来在没有 Key 时跑通流程。

## 异步处理

上传后马上返回，后台慢慢处理。用户不用一直等待，处理完再查状态。

## 混合检索

向量检索 + 关键词检索，两个结果合并。比单一检索更准。

## Rerank

对第一轮检索结果再排序，把最相关的排前面。

## EXPLAIN

数据库提供的执行计划，用来分析 SQL 为什么慢。后续 SQL 诊断会用到。
