# DevMind 后续开发计划（一次一阶段）

## 执行规则

- 一次只做一个阶段；
- 每个阶段必须完整走完：实现 -> 单元测试 -> 真实接口验证 -> 更新文档 -> 汇报；
- 一个阶段验收通过后，才开始下一个阶段；
- 不在一个阶段里混入其他阶段的功能；
- 每个阶段完成后，项目都必须保持可启动、可演示；
- 遇到必须由用户决策的问题，先停下来说明，不自己乱猜。

## 当前已完成

- MVP：文档上传、解析、切块、向量化、RAG 问答、引用来源；
- 阶段七：异步文档处理和任务重试；
- 阶段八：用户、权限隔离、混合检索、Rerank、审计日志；
- 阶段九：SQL 执行计划智能诊断。

## 阶段 A：前端管理界面

目标：不用命令行，打开浏览器就能使用 DevMind。

做什么：

1. 知识库列表和创建页面；
2. 文档上传、状态查看、删除；
3. 问答页面，展示回答和引用来源；
4. 任务状态页面；
5. SQL 诊断页面；
6. 登录态先用 `X-User-Id` 模拟，不做复杂鉴权。

验收标准：

- 浏览器里能完成“建库 -> 上传 -> 问答 -> 看引用”；
- 文档处理中能看到 `PROCESSING`，完成后变 `COMPLETED`；
- SQL 诊断页面能展示执行计划和风险；
- 移动端和桌面端布局都不错。

预计工作量：中到大。

### 阶段 C 完成情况

已完成：

- 新增 `RerankService`，支持 `heuristic` 和 `model` 两种模式；
- `ModelReranker` 调用大模型对检索结果排序，失败自动回退启发式；
- 新增 20 条 MySQL 检索评估问题；
- 新增评估接口 `POST /api/evaluations/retrieval`；

## 阶段 B：一键部署与 CI/CD

目标：别人拿到项目后，两条命令就能跑起来。

做什么：

1. 把后端、PostgreSQL、pgvector 全部放进 Docker Compose；
2. 提供 `.env.example`，所有 Key 从环境变量读取；
3. 增加 GitHub Actions：自动跑测试、打包镜像；
4. 增加一键启动脚本；
5. 增加部署文档。

验收标准：

- 新机器执行 `docker compose up -d` 后健康检查通过；
- 没有 API Key 也能用 mock 模式完整演示；
- CI 每次提交自动跑 `mvn test`；
- 文档说明清楚如何配置真实模型。

预计工作量：中。

### 阶段 B 完成情况

已完成：

- 多阶段 Dockerfile；
- Docker Compose 同时启动 PostgreSQL + 后端；
- `.env.example` 环境变量模板；
- `scripts/start.ps1` 和 `scripts/start.sh` 一键启动脚本；
- GitHub Actions CI：自动跑测试和打包；
- 阿里云 Maven 镜像配置，解决容器内网络问题；
- 一键部署文档。

已验证：

- `docker compose up -d` 成功；
- 后端健康检查 `UP`；
- 页面 `http://localhost:8080/` 返回 200。

## 阶段 C：模型 Rerank 与检索评估

目标：把启发式排序换成真实模型排序，并量化检索效果。

做什么：

1. 接入一个 Rerank 模型（如 OpenAI-compatible 或本地模型）；
2. 检索结果先召回 20 条，再 Rerank 取前 5 条；
3. 准备 20 条评估问题，记录每条问题 Top-5 是否命中正确答案；
4. 输出检索准确率报告；
5. Rerank 失败时自动回退到启发式排序。

验收标准：

- 有 Rerank 时比纯向量检索的命中率更高；
- 评估结果写进文档；
- 模型不可用时系统不崩溃。

预计工作量：中到大。

## 阶段 D：多模型路由与 Token 成本统计

目标：同一个问题可以根据场景选择不同模型，并记录花了多少钱。

做什么：

1. 配置多个模型供应商；
2. 按简单规则路由：普通问答、SQL 诊断、成本优先；
3. 每次模型调用记录模型名、Token 数、估算费用；
4. 提供成本统计接口；
5. 模型调用失败自动切换备用模型。

验收标准：

- 同一个问题可以路由到不同模型；
- 问答和 SQL 诊断都记录 Token 与费用；
- 主模型失败时自动切备用模型；
- 成本统计页面或接口可查看。

预计工作量：中到大。

### 阶段 D 完成情况

已完成：

- 新增 `model_usage` 表，记录每次模型调用；
- 问答、SQL 诊断、检索评估都会记录场景、模型、Token 和估算费用；
- 新增 `GET /api/model-usage` 和 `GET /api/model-usage/summary` 接口；
- 新增 `ChatRouter`：主模型失败时自动切换备用模型；
- 成本单价可通过环境变量配置。

已验证：

- 问答和 SQL 诊断各记录一条用量；
- 汇总接口正确返回调用次数和费用；
- 备用模型未配置时不影响 mock 模式。

## 阶段 E：文档版本与团队协作增强

目标：同一份文档可以更新版本，多个用户可以共享知识库。

做什么：

1. 文档增加版本号；
2. 更新文档时保留旧版本；
3. 支持回滚到旧版本；
4. 知识库支持多个成员，区分 owner 和 member；
5. 成员操作写入审计日志。

验收标准：

- 文档更新后旧向量和旧内容可回滚；
- 非成员不能访问知识库；
- 成员可以看到共享知识库但只有 owner 能删除；
- 审计日志包含成员操作。

预计工作量：大。

### 阶段 E 完成情况

已完成：

- 文档增加版本号；
- 更新文档时保留旧版本快照；
- 支持查看版本历史和回滚；
- 知识库支持多成员，区分 OWNER / MEMBER；
- 成员接口：添加、列表、移除；
- 成员操作写入审计日志；
- Docker 数据目录挂载，回滚文件可读取。

已验证：

- 成员 Bob 可以看到共享知识库；
- 更新文档后版本列表出现旧版本；
- 回滚到版本 1 后任务成功、文档恢复 4 个文本块。

## 不建议做的

- 不拆微服务；
- 不引入 Kafka / RocketMQ / ES / Milvus；
- 不做复杂 Agent；
- 不自动执行 AI 生成的 SQL；
- 不在没有评估样本时宣称检索准确率。
