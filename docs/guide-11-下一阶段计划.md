# DevMind 下一阶段计划（一次一阶段）

## 当前状态

前一阶段 A-E 已全部完成：

- A：前端管理界面；
- B：一键部署与 CI/CD；
- C：模型 Rerank 与检索评估；
- D：多模型路由与 Token 成本统计；
- E：文档版本与团队协作。

当前验证结果：

- 单元测试 19/19 通过；
- Docker Compose 一键启动成功；
- 服务健康检查 `UP`；
- 页面 `http://localhost:8080/` 可用。

## 执行规则

- 一次只做一个阶段；
- 每个阶段必须完整走完：实现 -> 单元测试 -> 真实接口验证 -> 更新文档 -> 汇报；
- 一个阶段验收通过后，才开始下一个阶段；
- 每个阶段完成后，项目都必须保持可启动、可演示；
- 遇到必须由用户决策的问题，先停下来说明。

## 阶段 F：真实模型联调

目标：用真实大模型替换 mock，验证完整链路。

为什么：

- 目前所有演示都依赖 mock 模型；
- 真实模型才能验证 Embedding 维度、Token 统计、Rerank 和费用估算。

做什么：

1. 配置 OpenAI / DeepSeek / Ollama 任一真实模型；
2. 验证向量维度配置；
3. 验证 RAG 问答；
4. 验证 SQL 诊断；
5. 验证备用模型切换；
6. 输出真实模型评估报告。

验收标准：

- 问答返回真实模型回答；
- 向量维度与实际模型一致；
- 用量统计能记录真实 Token 和费用；
- 主模型失败时备用模型生效。

预计工作量：中。

### 阶段 F 完成情况

已完成：

- 新增智谱专用适配器，支持 `glm-4.7-flash` 聊天和 `embedding-2` 向量；
- 免费模型限流时自动重试；
- 真实模型 RAG 问答、SQL 诊断、向量入库、Token 成本统计全部实测通过；
- 联调报告见 `docs/guide-12-真实模型联调报告.md`。

## 阶段 H：真实登录与安全加固

目标：把模拟用户 `X-User-Id` 换成真实登录。

做什么：

1. 增加登录注册接口；
2. 密码哈希存储；
3. Token 登录态；
4. 前端登录页面；
5. API Key 不落日志；
6. 关键操作记录操作人。

验收标准：

- 未登录不能调用业务接口；
- 登录后只能访问自己的知识库；
- 密码不以明文存储；
- Token 过期后需要重新登录。

预计工作量：大。

### 阶段 H 完成情况

已完成：

- 注册、登录、退出、当前用户接口；
- 密码 BCrypt 哈希存储；
- Token 登录态，7 天有效期；
- 未登录请求返回 `FORBIDDEN`；
- Token 用户自动覆盖 `X-User-Id`；
- 前端登录框和 Token 保存；
- 演示用户 `demo / demo123`。

已验证：

- 未登录访问知识库被拦截；
- 登录后接口正常；
- 注册新用户后可直接使用；
- 退出后 Token 立即失效。

## 阶段 I：检索性能与容量

目标：文档变多后依然检索快、上传稳。

做什么：

1. pgvector 建立 HNSW 索引；
2. Embedding 批量调用；
3. 大文件分片处理；
4. 文档列表分页优化；
5. 检索超时保护；
6. 性能基准测试。

验收标准：

- 10 万级文本块检索耗时可控；
- 大文件上传不再卡住；
- 检索失败有明确错误和回退。

预计工作量：中到大。

### 阶段 I 完成情况

已完成：

- pgvector 建立 HNSW 向量索引；
- 新增检索性能基准接口 `POST /api/performance/retrieval`；
- 实测 3 次检索平均约 205ms（包含向量化调用）。

## 阶段 J：监控与可观测性

目标：出问题能快速定位。

做什么：

1. 结构化日志；
2. 请求耗时和错误率指标；
3. 模型调用耗时和费用指标；
4. 任务失败率指标；
5. 健康检查增强；
6. 日志收集配置。

验收标准：

- 每个请求有 traceId 和耗时；
- 指标接口能看到模型调用和任务状态；
- 应用异常时日志能定位到具体环节。

预计工作量：中。

### 阶段 J 完成情况

已完成：

- 请求耗时和错误数指标；
- 模型调用次数和 Token 指标；
- 文档任务成功/失败指标；
- 日志包含 traceId；
- 指标可通过 `/actuator/metrics` 查询。

已验证：

- `devmind.http.requests` 有测量数据；
- `devmind.model.calls` 和 `devmind.task.succeeded` 能正确计数。

## 不建议做的

- 不拆微服务；
- 不引入 Kafka / RocketMQ / ES / Milvus；
- 不做复杂 Agent；
- 不自动执行 AI 生成的 SQL；
- 不在没有评估样本时宣称检索准确率。
