- 一次只做一个阶段；
- 每个阶段必须完整走完：实现 -> 单元测试 -> 真实接口验证 -> 更新文档 -> 汇报；
- 一个阶段验收通过后，才开始下一个阶段；
- 每个阶段完成后，项目都必须保持可启动、可演示；
- 遇到必须由用户决策的问题，先停下来说明。

## 阶段 M：检索质量提升

目标：让回答更准，引用更可靠。

为什么：

- 当前评估命中率 90%，还有提升空间；
- 需要更多样本文本和真实 Rerank 模型。

做什么：

1. 扩充评估样本到 50 条；
2. 增加文档元数据过滤；
3. 接入真实 Rerank 模型；
4. 对比不同切块策略；
5. 输出检索质量对比报告。

验收标准：

- 评估样本 50 条以上；
- 命中率相比当前有提升；
- 报告记录不同方案对比；
- 切换方案可回退。

预计工作量：中到大。

### 阶段 M 完成情况

已完成：

- 评估样本从 20 条扩充到 50 条（MySQL 索引 20 + SQL 优化 10 + RAG 检索 10 + 运维容量 10）；
- 文档元数据：`document` 表新增 `metadata JSONB`，上传支持标签（逗号分隔），chunk 元数据合并文档标签；
- 检索元数据过滤：向量检索、关键词检索、混合检索均支持 `metadata @> jsonb` 过滤，问答/评估接口支持 `tags` 参数；
- 真实 Rerank：评估接口支持 `rerankMode=heuristic|model`，model 模式调用真实模型排序，失败自动回退 heuristic；
- 切块策略：新增 `FixedSizeTextChunker`（固定大小），`devmind.chunker-strategy` 支持 `boundary|fixed` 切换；
- 对比测试：新增 `TextChunkerComparisonTest`（3 个用例）对比两种切块策略。

已验证：

- 前端 21/21、后端 22/22 测试通过；
- 50 条评估实测：heuristic 命中率 56%（MySQL 主题 26/30，RAG/运维主题暴露盲区）；
- 标签过滤问答实测：`tags=[redis]` 只返回对应文档引用；
- 真实模型 Rerank 在智谱限流时自动回退启发式，验证可回退；
- 详细对比见 `docs/guide-16-检索质量对比报告.md`。

预计工作量：大。

### 阶段 N 完成情况

已完成：

## 阶段 O：安全与稳定性加固

目标：降低被攻击和故障风险。

为什么：

- 已有登录，但还需要防刷、限流和密钥保护。

做什么：

1. 登录失败次数限制；
2. 接口限流；
3. API Key 加密存储；
4. Token 刷新机制；
5. 请求敏感字段脱敏；
6. 故障注入测试和恢复演练。

验收标准：

- 暴力登录会被拦截；
- 高频请求会被限流；
- API Key 不以明文存储；
- 模拟故障后服务能恢复。

预计工作量：中到大。

### 阶段 O 完成情况

已完成：

- 登录失败限制：`LoginAttemptService`，连错 5 次锁定 10 分钟，锁定期间正确密码也拒绝（429 ACCOUNT_LOCKED）；
- 接口限流：`RateLimitInterceptor` 固定窗口（按路径+用户），登录接口独立更严配额（默认 10/分钟），超限 429 RATE_LIMITED；
- API Key 加密：`SecretCipher`（AES/GCM），配置支持 `enc:` 前缀密文，主密钥取环境变量或自动生成到 `data/secret.key`；智谱/备用模型 key 运行时解密；管理员接口生成加密值；
- Token 滑动续期：剩余有效期低于 2 天自动延长到 7 天，长期活跃免重登；
- 敏感字段脱敏：logback pattern `%replace` 屏蔽 `Bearer xxx`；`SensitiveDataMasker` 工具；
- 故障演练：`scripts/fault-drill.ps1`（重启策略/容器恢复/数据库中断自愈/登录可用性），详细见 `docs/guide-18-安全加固与故障演练.md`。

已验证：

- 后端 43/43 测试通过；
- 暴力登录实测被拦截（正确密码也 429）；
- 高频请求实测被限流（429）；
- API Key 加密值不含明文；
- Token 续期实测 1 天 → 自动延长到 7 天；
- 故障演练 PASS：数据库中断后应用自愈（Hikari 重连，无需重启容器）。
