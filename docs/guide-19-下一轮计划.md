## 执行规则

- 一次只做一个阶段；
- 每个阶段必须完整走完：实现 -> 单元测试 -> 真实接口验证 -> 更新文档 -> 汇报；
- 一个阶段验收通过后，才开始下一个阶段；
- 每个阶段完成后，项目都必须保持可启动、可演示；
- 遇到必须由用户决策的问题，先停下来说明。

## 阶段 P：检索与问答质量进阶

目标：提升检索命中率与回答质量，让问答带上多轮语境。

为什么：

- 当前命中率 56%，RAG/运维主题偏弱，是产品核心短板；
- 当前问答每次都是单轮，无法承接多轮追问；
- 真实 Rerank 模型链路受智谱限流影响不稳定。

做什么：

1. 查询改写：把口语/短问句改写为更适合检索的查询（同义词、展开、拆子问题）；
2. 多轮对话上下文注入：问答接口利用会话历史，把上下文问题与追问组合后检索；
3. 真实 Rerank 全链路打通：智谱 429 退避重试、失败自动回退 heuristic（已有回退，需加强重试）；
4. 评估样本细化：按主题分组统计，输出主题级命中率报告，定位盲区。

验收标准：

- 整体命中率相比 56% 有提升（目标 65%+）；
- 多轮追问能结合上下文命中；
- 真实 Rerank 在限流下能稳定回退/重试；
- 评估报告按主题给出命中率。

预计工作量：中到大。

### 阶段 P 完成情况

已完成：

- 查询改写：`QueryRewriter`（启发式，无模型依赖），把含指代词的追问改写为完整检索查询（如「它为什么慢」+ 历史「深分页怎么优化」-> 「深分页 为什么慢」）；
- 多轮对话上下文注入：`ChatService` 加载最近 3 轮会话历史，检索用改写后的查询，模型 prompt 携带历史对话；
- 真实 Rerank 稳定性：`ZhipuRestModelGateway` 429 限流使用更长指数退避（5s 起步），模型失败仍自动回退启发式；
- 评估主题级统计：50 条样本按 4 个主题（MySQL索引/SQL优化/RAG检索/运维容量）分组，响应与前端展示主题命中率。

已验证：

- 后端 48/48（新增 `QueryRewriterTest` 5 例）、前端 21/21 测试通过；
- 多轮对话端到端：第 1 问「深分页怎么优化」命中 MySQL索引文档，追问「它为什么慢」（带会话）改写后命中同一文档且 score 0.79，回答引用「深分页为什么慢」；
- 浏览器实测评估页「按主题」表格正常渲染。

补充文档后的最终评估（kb=3，heuristic）：

- 补文档前：整体 28/50=56%，RAG检索 0%、运维容量 20%（文档盲区）；
- 补充 `examples/RAG检索专题.md`、`examples/运维容量专题.md` 后：**整体 45/50=90%**，MySQL索引 17/20=85%、SQL优化 8/10=80%、RAG检索 10/10=100%、运维容量 10/10=100%；
- 命中率目标（65%+）达成，验证盲区为文档覆盖而非检索算法。

## 阶段 Q：AI 能力真实化

目标：让所有 AI 能力都走真实模型并可控成本。

为什么：

- SQL 诊断仍为规则引擎（mock），没有接入真实模型；
- 对话历史不可管理；
- 模型调用无配额，容易被刷爆。

做什么：

1. SQL 诊断接入真实模型（复用智谱链路，规则引擎作为回退）；
2. 会话历史管理（列表/删除/续聊）；
3. 用量配额：按团队/用户限制每日调用次数。

验收标准：

- SQL 诊断真实模型回答可演示，规则引擎可回退；
- 会话可列出、删除、续聊；
- 超配额调用被拦截。

预计工作量：中到大。

### 阶段 Q 完成情况

已完成：

- SQL 诊断真实模型链路：建议生成已走真实模型（ChatRouter），模型失败自动回退规则引擎生成的结构化建议（不再抛 502）；
- 会话历史管理：`chat_conversation` 记录归属用户；新增 `GET /api/conversations`（列表）、`DELETE /api/conversations/{id}`（删除，带归属校验）；前端问答页新增「历史会话」面板（列表/切换续聊/删除/新建）；
- 用量配额：`DevMindQuotaProperties`（`devmind.quota.daily-calls-limit` / `daily-cost-limit`，0=不限），`ModelUsageService` 按用户统计当日调用/费用，超限返回 `429 QUOTA_EXCEEDED`；评估场景不参与配额。

已验证：

- 后端 51/51（新增 `ModelUsageServiceTest` 3 例）、前端 21/21 测试通过；
- SQL 诊断实测：`riskLevel=HIGH`，建议含全表扫描/文件排序/深分页诊断与复合索引建议，引用知识库参考资料；
- 会话管理实测：创建会话 -> 列表可见 -> 查看消息 -> 删除 -> 越权删除（他人）返回 404；
- 浏览器实测：问答页「历史会话」面板列表/切换加载回答/新建/删除均正常。

1. 接入 Prometheus 指标（请求量、延迟、模型调用失败率、429 次数、token 用量）；
2. 告警规则（健康检查、模型失败率、数据库连接池）；
3. Grafana 面板示例（可选）。

验收标准：

- `/actuator/prometheus` 暴露指标；
- 关键告警规则可触发。

预计工作量：中。

### 阶段 R 完成情况

已完成：

- 依赖 `micrometer-registry-prometheus`，暴露 `/actuator/prometheus` 端点；
- 自定义指标：模型调用耗时 `devmind.model.calls.duration`、失败计数 `devmind.model.calls.failed`（ChatRouter）、调用/Token 计数（ModelUsageService 已有）、限流拦截 `devmind.rate.limited`、账号锁定 `devmind.login.locked`；

- 告警规则示例 `prometheus/rules.yml`（服务不可达/模型失败率/限流爆发/疑似暴力登录/连接池占满/5xx 错误率）；
- Grafana 面板示例 `prometheus/grafana-dashboard.json`（请求/延迟/模型/限流/连接池/JVM）。

已验证：

- `/actuator/prometheus` 返回指标；
- 实测指标出现：`devmind_model_calls_duration_seconds_sum=23.9`（真实模型链路耗时）、`devmind_model_calls_total{scene=sql}=1`、`devmind_login_locked_total=1`、HTTP 请求指标、`devmind_model_calls_failed_total=0`；
- 后端 51/51 测试通过。

## 不建议做的

- 不拆微服务；
- 不引入 Kafka / RocketMQ / ES / Milvus；
- 不做复杂 Agent；
- 不自动执行 AI 生成的 SQL；
- 不在没有评估样本时宣称检索准确率。
