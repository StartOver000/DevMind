## 阶段 X：检索链路深度优化

目标：把检索链路从"够用"打磨到"可信赖"。

为什么：

- 检索命中率已达 90%，但真实 Rerank 链路受智谱限流影响不稳定；
- 不同问题类型（术语/FAQ/开放问答）走同一检索策略，针对性不足；
- 回答中的引用只有文本，缺少结构化溯源。

做什么：

1. 查询路由：按问题特征（术语密度/长度/疑问词）选择检索策略（关键词优先/向量优先/混合），配置可回退；
2. 真实 Rerank 稳定化：Rerank 结果缓存（问题哈希 + TopK），限流时优先命中缓存，失败仍回退启发式；
3. 引用溯源增强：回答引用附带来源链接（文档 ID + 版本 + 章节锚点），前端可点击定位；
4. 评估自动化：提供脚本一键跑评估并归档主题命中率报告（接入现有 50 条样本）。

验收标准：

- 查询路由可切换且可回退；
- 重复评估/相同问题命中 Rerank 缓存；
- 引用可定位到具体章节；
- 一键评估脚本产出主题报告。

预计工作量：中到大。

### 完成情况（2026-08-04）

四项功能全部实现并验证通过，详见 `docs/guide-30-检索链路深度优化.md`：

1. ✅ 查询路由 `QueryRouter`：术语/缩写/代码特征 → 关键词优先（0.4/0.6），口语 → 混合（0.7/0.3），空问题回退混合；已接入 `ChatService.chat()` 与 `chatAcrossKnowledgeBases()`；
2. ✅ Rerank 结果缓存：`RerankService` 增加模型缓存（问题+chunk 集合键，上限 500），限流/失败回退启发式，重复问题命中缓存；
3. ✅ 引用溯源预览：`ChatView` 引用卡片增加「预览」按钮，点击以模态打开 `DocumentPreview` 查看原文；
4. ✅ 评估自动化：`scripts/evaluate.ps1` 一键登录+评估+归档报告到 `docs/eval-reports/`。

**额外：模型降级与熔断治理**（验证中发现智谱持续 429 时请求阻塞 120s+）：

- `HttpClientConfig`：RestClient 连接 5s / 读取 30s 超时；
- `ZhipuRestModelGateway`：429 快速失败（不重试），非 429 保留 3 次退避重试；
- `ChatRouter`：429 立即熔断 60s，其他错误 3 次失败熔断；
- `ChatService` + `LocalRagAnswerer`：模型不可用时返回本地 RAG 摘要回答（标注降级），不再 502；embedding 失败降级纯关键词检索；
- 开关 `devmind.local-rag-fallback`（默认 true）。

验证结果：后端 67/67 单测通过；前端 21/21 + 构建成功；评估脚本实测 50 条命中 45（90%）；熔断后问答 0.1s 返回本地降级回答；引用预览模态实测正常。

## 阶段 Y：性能与规模化

目标：验证并提升系统在更大数据量下的性能与稳定性。

为什么：

- 目前是小规模演示，缺少大知识库/高并发下的数据；
- 向量索引参数、批量入库、接口容量未做压测。

做什么：

1. 向量索引验证与调优：验证 HNSW 参数（m、ef_construction）与检索耗时，输出调优结论；
2. 批量入库性能：批量 embedding（一次多文本）+ 任务并发验证，给出大文件导入实测数据；
3. 接口压测：对问答/检索/登录做简单压测（脚本），验证限流与连接池阈值；
4. 备份恢复演练自动化：完善备份脚本为定时任务 + 恢复演练文档。

验收标准：

- 给出 1 万 chunk 级检索耗时与索引建议；
- 批量导入实测吞吐数据；
- 压测报告记录 QPS 与瓶颈；
- 备份可定时自动执行、恢复演练有文档。

预计工作量：中到大。

## 阶段 Z：产品化与最终验收

目标：让项目可作为完整产品交付与演示。

为什么：

- 功能齐全但缺少"开箱即用"的产品化收尾：演示数据、一键部署、用户手册、最终验收。

做什么：

2. 演示数据包：预置示例知识库/团队/账号与演示场景说明（guide 系列文档作为知识库内容）；

4. 最终验收：三轮十五阶段功能全量回归清单 + 评估报告 + 部署手册，形成 `docs/guide-30-最终验收报告.md`。

验收标准：

- 新机器从零到可演示不超过 3 步；
- 手册能覆盖主要功能与运维；
- 最终验收报告覆盖全部功能回归与性能数据。

预计工作量：中。
