# DevMind 人工验收清单

> 用途：项目功能已全部由 AI 实现并通过自动化验证。本文档供**人工验收与接管**使用，
> 按优先级列出需要人类确认/调整的点，并如实记录已知技术债。

## 验收顺序建议

```text
P0 安全与合规  ->  P1 业务正确性  ->  P2 工程质量  ->  P3 运维与数据  ->  P4 文档一致性
```

## 已知技术债（如实记录）

1. `auth-enabled` 默认 `false`：演示便利 vs 生产安全，需在部署层强制。
2. 无集成/API 层测试、前端无 E2E：回归保障主要靠 67+21 个单元测试。
3. 依赖 CVE 未扫描过（Spring Boot 3.3.4 / Spring AI 1.0.0 / Tika 2.9.2 等）。
4. `RerankService` 缓存达到 500 条整体清空（简单但不够精细）。
5. 熔断窗口 60s、超时 5s/30s 为硬编码常量，未配置化。
6. `DevMindProperties` 40+ 字段且含历史遗留（如 `modelFallback*`、`cost*`），可清理合并。
7. 阶段 Y（HNSW 调优/批量入库压测/接口压测）与阶段 Z（产品化收尾）尚未实施。
8. 部分幂等/并发边界（如任务并发、embedding 缓存并发写）未经高并发验证。

## 建议接管顺序（供参考）

1. 先跑 P0 全部 8 项（半天内可完成）；
2. 补 1-2 条核心链路集成测试（上传→检索→问答，`@SpringBootTest` + Testcontainers 或 mock DB）；
3. 跑 CVE 扫描并修复高危；
4. 人工评审 `ai/`、`chat/`、`document/` 三个核心包（AI 生成代码密集区）；
5. 清理演示数据 + 执行一次备份恢复演练；
6. 校对 guide 文档关键章节（环境变量、接口、配置）；
7. 之后按需决定是否继续阶段 Y/Z。
