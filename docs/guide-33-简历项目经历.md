## 一、一句话简介（简历标题/口头介绍用）

> 面向研发团队的 AI 知识检索与智能诊断平台：文档向量化入库 → RAG 混合检索问答（引用可溯源）→ SQL 执行计划诊断，含多租户隔离与模型限流降级熔断治理。

## 二、项目经历正文模板（可直接粘贴）

**DevMind — AI 知识检索与智能诊断平台**（个人全栈项目）
Java 17 · Spring Boot 3.3.13 · Spring AI 1.0.0 · PostgreSQL 16 + pgvector · Apache Tika · Vue 3 + Vite · Vitest + Playwright · Prometheus/Grafana · Docker Compose

**项目描述**：从零设计并实现面向研发团队的 RAG 知识检索平台。支持文档上传解析（Markdown/PDF）、异步切块向量化入库（内容哈希去重）、混合检索（向量 + 关键词权重融合）、模型/启发式双模式 Rerank、引用溯源、多轮多库聚合问答、SQL 执行计划诊断；配套多租户权限、用量配额、检索评估、监控告警与一键部署。

**个人职责**（简历正文用下面 4~5 条融合版即可，完整 STAR 见第三节）：

- 独立完成前后端全链路设计与开发：RAG 检索链路（解析→切块→向量化→混合检索→Rerank→引用）、异步任务与幂等去重、版本回滚与向量重建一致性。
- 设计并落地大模型调用韧性治理：429 快速失败、连接/读取超时、分级熔断、本地 RAG/关键词/备用模型三级兜底，把模型挂起 120s+ 的体验问题压到熔断后 0.1s 返回。
- 基于 PostgreSQL 16 + pgvector 实现 1024 维向量检索，混合检索分数融合与阈值过滤，配合 50 条评估样本量化命中率、驱动参数调优。
- 实现多租户三级权限体系（知识库成员/团队成员/管理员）与越权 403 拦截、审计日志、登录/接口限流、用量配额。
- 文档数据链路一致性：异步任务入库（状态机+重试）、SHA-256 幂等去重、版本快照回滚后自动重建向量，保证文件态与向量索引强一致。

> **工程数据背书**（不作为职责条目，面试被问"怎么保证质量/安全"时引用）：
> 后端 72 测试（67 单测 + 5 集成）、前端 28 单测 + Playwright E2E 全绿；Spring Boot 3.3.4→3.3.13 安全升级（修复 Spring CVE）、前端 npm audit 5→0、GitHub Dependabot 依赖巡检。

## 三、主推 5 点个人职责（STAR 版）

### 1. RAG 检索链路全栈设计与调优 ⭐
**【简历版】**
> 从零设计文档入库到问答的完整 RAG 链路（解析→切块→向量化→混合检索→Rerank→引用溯源），实现查询路由、向量+关键词 0.7/0.3 融合、双模式 Rerank 自动回退，配合 50 条评估样本将检索阈值（0.35）与 Top-K（5）调至可用水平。

**【面试讲述版】**
- **S（情境）**：知识库问答初期仅单一向量检索，专有术语匹配差、相关片段召回不全，且检索效果无量化依据。
- **T（任务）**：构建完整、可评估、可调优的 RAG 检索链路。
- **A（行动）**：① Tika 解析 + 标题边界切块（含重叠区间保留上下文）；② QueryRouter 查询路由分流；③ 向量 + 关键词 0.7/0.3 混合检索分数融合；④ 模型/启发式双模式 Rerank 及失败自动回退；⑤ 建立 50 条"问题+期望关键词"样本量化命中率。
- **R（结果）**：检索链路全链路可测，参数调整有量化依据（评估报告见 docs/guide-10），命中率可按主题分组定位盲区。

---

### 2. 大模型调用韧性治理（限流/超时/熔断/降级）⭐ 最能打的点
**【简历版】**
> 针对外部模型 429 限流与 120s+ 无响应挂起，设计四层韧性治理——429 快速失败、5s/30s 超时、分级熔断（429 立即熔断 60s）、本地 RAG+关键词+备用模型三级降级，将挂起问题压至熔断后 0.1s 返回，外部模型不可用时功能不中断。

**【面试讲述版】**
- **S（情境）**：接入智谱真实模型后遭遇账户级 429 限流与最长 120s+ 无响应挂起，问答/诊断体验不可用。
- **T（任务）**：在外部模型不可控的前提下，保证功能可用性与响应稳定。
- **A（行动）**：① 识别 429 并快速失败不重试；② RestClient 连接 5s / 读取 30s 超时；③ 分级熔断——429 立即熔断 60s、常规错误 3 次触发；④ 本地 RAG 摘要、关键词检索、备用模型三级兜底。
- **R（结果）**：模型挂起从 120s+ 收敛为 30s 超时兜底；熔断窗口内 **0.1s** 返回本地降级；降级链路有自动化测试覆盖（含集成用例）。

---

### 3. 向量数据库与检索工程
**【简历版】**
> 基于 PostgreSQL 16 + pgvector 实现 1024 维向量存储与混合检索（分数融合+最低阈值过滤），实现 Embedding 内容哈希缓存与失败降级，模型不可用时检索链路不中断。

**【面试讲述版】**
- **S（情境）**：向量检索依赖外部 Embedding 服务，限流/故障时检索整体不可用，且重复内容会重复调用模型产生浪费。
- **T（任务）**：让检索链路稳定、低成本、不依赖外部服务可用性。
- **A（行动）**：① pgvector 1024 维向量存储与检索；② 混合检索分数融合 + 最低相似度阈值过滤；③ Embedding 以内容哈希为 key 的缓存命中复用；④ Embedding 失败自动降级为纯关键词检索。
- **R（结果）**：模型不可用时检索仍可用（关键词降级）；重复入库/重复查询复用缓存减少模型调用。

### 4. 多租户隔离与权限模型
**【简历版】**
> 实现知识库成员/团队成员/管理员三级权限与越权 403 拦截，配套审计日志、登录/接口限流（10/min、120/min）、每日用量费用配额，鉴权一键开关支持免登录演示。

**【面试讲述版】**
- **S（情境）**：多用户共享平台存在越权访问与滥用风险，同时演示场景需要免登录快速体验。
- **T（任务）**：保证数据隔离与权限可控，同时兼顾演示便利。
- **A（行动）**：① 三级权限模型（成员 MEMBER/OWNER、团队成员、全局管理员）；② 越权访问统一 403 拦截；③ 审计日志；④ 登录/接口限流 + 每日用量/费用配额；⑤ 鉴权开关（免登录模式）。
- **R（结果）**：越权拦截有集成测试验证（DevMindIntegrationTest）；免登录模式全流程可演示，配额超限自动拦截。

### 5. 文档数据链路一致性设计（异步任务 + 幂等去重 + 版本回滚）
**【简历版】**
> 设计文档异步入库任务（状态机+重试）、SHA-256 幂等去重（唯一约束兜底并发）、版本快照回滚并自动重建向量，保证文件态与向量索引强一致。

**【面试讲述版】**
- **S（情境）**：大文档入库耗时长需异步；重复上传与并发提交会重复入库；更新/回滚后文件与向量可能不一致。
- **T（任务）**：入库可靠不重复，回滚后检索结果一致。
- **A（行动）**：① document_task 异步任务状态机 + 最大重试；② SHA-256 内容哈希 + UNIQUE(knowledge_base_id, content_hash) 幂等去重；③ 更新/回滚前自动存快照，回滚后触发 reprocess 重建切块与向量；④ 版本对比 API。
- **R（结果）**：重复内容一次入库；回滚后检索结果与文件内容一致；入库过程可查任务状态、可重试。

- **R**：联调报告与检索评估报告齐全（docs/guide-12/guide-10），30+ 篇设计文档按阶段迭代。

- **S**：检索效果无量化依据，难以证明优化价值。
- **A**：建立 50 条"问题 + 期望关键词"样本库，实现命中率自动化评估，可按主题分组定位盲区。
- **R**：形成"评估 → 调优 → 再评估"闭环，参数调整（阈值/Top-K/权重/Rerank）有数据支撑。

- **S**：无 DBA 场景下，慢 SQL 根因难定位。
- **A**：EXPLAIN 解析 + 规则引擎初筛（高成本类型/索引缺失/深分页等风险识别）+ AI 生成优化建议。
- **R**：AI 失败时自动回退规则结果，诊断链路不中断。

## 五、面试追问题库（每条职责配 2~3 个追问 + 参考要点）

> 面试讲述版已按 STAR 结构组织，讲时按 S→T→A→R 顺序 1~2 分钟讲完。
> 面试官大概率从职责里挑一个深挖，提前准备"为什么 / 怎么做 / 效果如何"。

**针对职责 2（韧性治理）——最高频：**
- Q：为什么 429 不重试？
  A：429 是账户级限流，短时重试只会继续吃限流窗口，等退避等于拖慢整体体验；直接快速失败交给上层熔断更合理。
- Q：熔断为什么设 60s？
  A：覆盖限流窗口（智谱 60s 级窗口），熔断期内直接本地降级，保证业务可用；窗口结束后放行试探。
- Q：本地降级怎么保证回答质量？
  A：用检索到的 Top-K 片段做摘要式回答，并显式标注"本地降级模式"，避免用户误以为是模型原文。

**针对职责 5（数据一致性）：**
- Q：为什么用哈希去重而不是比对内容？
  A：SHA-256 + `UNIQUE(knowledge_base_id, content_hash)` 把并发去重兜在数据库层，代价是单次 O(文件大小) 计算，一次入库即判重。
- Q：回滚怎么保证向量不错乱？
  A：先存当前版本快照 → 替换文件记录 → 触发 reprocess 重建切块与向量，三步串行保证文件态与索引一致。
- Q：异步任务失败怎么办？
  A：任务表 + 状态机 + 最大重试次数，失败可查任务状态、可重试，避免整条入库链路阻塞。

**针对职责 3（向量检索）：**
- Q：混合检索为什么是 0.7/0.3？
  A：语义为主、术语为辅；专有名词靠关键词精确匹配，语义表达靠向量，先按经验初设再用评估样本实测调整。
- Q：Embedding 缓存怎么做的？
  A：以内容哈希为 key，命中直接复用向量，省一次模型调用，同时天然支持文档去重场景。
