## 三、主推 5 点个人职责（重点用这套）

### 1. RAG 检索链路全栈设计与调优 ⭐
从零设计文档入库到问答的完整链路：解析（Tika）→ 切块（标题边界 + 重叠区间）→ Embedding → pgvector 入库 → 混合检索 → Rerank → 引用溯源。针对检索精度实现 QueryRouter 查询路由、向量 + 关键词 0.7/0.3 权重融合、模型/启发式双模式 Rerank 及失败自动回退，并用 50 条评估样本量化命中率、驱动阈值（0.35）与 Top-K（5）调优。

### 2. 大模型调用韧性治理（限流/超时/熔断/降级）⭐ 最能打的点
应对外部模型 429 限流与不可控延迟，设计四层治理：429 快速失败不重试、RestClient 连接 5s / 读取 30s 超时、按错误类型分级熔断（429 立即熔断 60s / 常规错误 3 次触发）、本地 RAG 摘要 + 关键词检索 + 备用模型三级兜底。实测把模型调用 120s+ 挂起问题压到熔断后 **0.1s** 返回本地降级。

### 3. 向量数据库与检索工程
基于 PostgreSQL 16 + pgvector 设计 1024 维向量存储与检索，实现混合检索分数融合与最低相似度阈值过滤；实现 Embedding 缓存（内容哈希命中免重复调用）与失败降级，保证模型不可用时检索链路不中断。

### 4. 多租户隔离与权限模型
设计并实现知识库成员（MEMBER/OWNER）/ 团队成员 / 全局管理员三级权限体系，越权访问统一 403 拦截；配套审计日志、登录限流（10/min）与接口限流（120/min）、每日用量/费用配额（超限自动拦截），鉴权支持一键开关（免登录演示模式）。

### 5. 文档数据链路一致性设计（异步任务 + 幂等去重 + 版本回滚）
设计文档入库异步任务体系：上传即返回任务 ID，后台流水线完成解析→切块→向量化，含状态机与失败重试；用 SHA-256 内容哈希 + 数据库唯一约束实现幂等去重，避免并发重复入库；实现版本快照与回滚——更新/回滚前自动存快照，回滚后**自动触发向量重建**（重新切块 + Embedding），保证文件态与向量索引强一致，并提供版本对比 API。

## 五、面试追问题库（每条职责配 2~3 个追问 + 参考要点）

> 面试官大概率从职责里挑一个深挖，提前准备"为什么 / 怎么做 / 效果如何"。

**针对职责 2（韧性治理）——最高频：**
- Q：为什么 429 不重试？
  A：429 是账户级限流，短时重试只会继续吃限流窗口，等退避等于拖慢整体体验；直接快速失败交给上层熔断更合理。
- Q：熔断为什么设 60s？
  A：覆盖限流窗口（智谱 60s 级窗口），熔断期内直接本地降级，保证业务可用；窗口结束后放行试探。
- Q：本地降级怎么保证回答质量？
  A：用检索到的 Top-K 片段做摘要式回答，并显式标注"本地降级模式"，避免用户误以为是模型原文。

**针对职责 5（数据一致性）：**
- Q：为什么用哈希去重而不是比对内容？
  A：SHA-256 + `UNIQUE(knowledge_base_id, content_hash)` 把并发去重兜在数据库层，代价是单次 O(文件大小) 计算，一次入库即判重。
- Q：回滚怎么保证向量不错乱？
  A：先存当前版本快照 → 替换文件记录 → 触发 reprocess 重建切块与向量，三步串行保证文件态与索引一致。
- Q：异步任务失败怎么办？
  A：任务表 + 状态机 + 最大重试次数，失败可查任务状态、可重试，避免整条入库链路阻塞。

**针对职责 3（向量检索）：**
- Q：混合检索为什么是 0.7/0.3？
  A：语义为主、术语为辅；专有名词靠关键词精确匹配，语义表达靠向量，先按经验初设再用评估样本实测调整。
- Q：Embedding 缓存怎么做的？
  A：以内容哈希为 key，命中直接复用向量，省一次模型调用，同时天然支持文档去重场景。
