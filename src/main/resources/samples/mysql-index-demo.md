# MySQL 索引速查（示例文档）

> 这是 DevMind 内置的示例文档，用于体验知识库检索：上传后直接提问
> 「什么是索引」「什么时候该建索引」「为什么我的查询慢」等，即可看到带引用的回答。

## 一、什么是索引

索引是数据库为了加速查询而建立的**有序数据结构**，类似书的目录。
没有索引时，数据库要**全表扫描**（一行行找）；有索引时，可以按顺序快速定位，复杂度从 O(n) 降到 O(log n)。

- 索引的本质：**以空间换时间**（多占存储，换查询速度）。
- 主键索引：每张表默认有一个，数据本身按主键有序存储（聚簇索引）。
- 二级索引（普通索引）：单独维护的索引结构，指向主键。

## 二、索引的类型

| 类型 | 说明 | 使用场景 |
|---|---|---|
| 普通索引（INDEX） | 加速查询 | 高频查询列 |
| 唯一索引（UNIQUE） | 加速 + 保证唯一 | 手机号、邮箱、订单号 |
| 主键索引（PRIMARY KEY） | 聚簇索引 | 每表一个 |
| 联合索引（组合索引） | 多个列一起建 | 多条件查询 |
| 全文索引（FULLTEXT） | 文本搜索 | 文章、评论 |
| 空间索引（SPATIAL） | 地理位置 | GIS 数据 |

## 三、什么时候该建索引

1. **WHERE 条件常用列**：`SELECT * FROM order WHERE user_id = ?` → 给 `user_id` 建索引。
2. **ORDER BY / GROUP BY 的列**：避免文件排序（filesort）。
3. **JOIN 的连接列**：两表连接字段都要有索引。
4. **区分度高的列**：列值越分散，索引效果越好（如 `status` 只有 3 个值，区分度低，索引收益小）。
5. **数据量大的表**：几千行以内全表扫描往往更快，索引反而拖累写入。

## 四、什么时候不该建索引

- **频繁更新的列**：每次更新都要同步改索引，写放大。
- **区分度极低的列**：如性别、状态（只有少量取值），优化器可能直接放弃索引。
- **超长文本列**：除非用前缀索引，否则索引巨大且慢。
- **小表**：全表扫描比走索引更快，建索引是浪费。

## 五、联合索引与最左前缀

联合索引 `(a, b, c)` 生效遵循**最左前缀原则**：

- ✅ `WHERE a = 1` 走索引
- ✅ `WHERE a = 1 AND b = 2` 走索引
- ✅ `WHERE a = 1 AND b = 2 AND c = 3` 走索引
- ❌ `WHERE b = 2` **不走**（跳过了最左列 a）
- ❌ `WHERE c = 3` **不走**

把**区分度高、等值查询**的列放前面，范围查询（`>`、`<`、`BETWEEN`）的列放后面，因为范围条件之后的列无法用到索引。

## 六、回表与覆盖索引

- **回表**：二级索引查到主键后，再回主键索引取整行数据。回表次数多 = 慢。
- **覆盖索引**：索引里已经包含查询需要的所有列，不需要回表。
  - 例：`SELECT name FROM user WHERE age = 20`，若 `(age, name)` 建了联合索引，则直接命中，不用回表。
- 所以**不要无脑 SELECT \***，只取需要的列更容易让优化器用上覆盖索引。

## 七、为什么我的查询慢（排查清单）

1. **没走索引**：`EXPLAIN` 看 `type` 列——`ALL` 表示全表扫描，`index`/`ref`/`eq_ref`/`const` 才说明用了索引。
2. **索引失效**：对索引列做函数运算（`WHERE YEAR(create_time)=2026`）、隐式类型转换、`LIKE '%xx'` 前置通配符、`OR` 连接非索引列，都会让索引失效。
3. **深分页**：`LIMIT 100000, 20` 要先扫描 10 万行再丢弃。优化：用上一页最后一条的 id 做游标（`WHERE id > ? LIMIT 20`）。
4. **filesort**：`ORDER BY` 列没索引 → 内存/磁盘文件排序，量大时极慢。
5. **索引选择错误**：数据分布变了，优化器选了错索引——可用 `FORCE INDEX` 临时验证。

## 八、EXPLAIN 关键字段速读

| 字段 | 含义 | 关注点 |
|---|---|---|
| type | 访问类型 | `ALL`=全表扫（危险）；`range`/`ref`/`eq_ref`/`const`=良好 |
| key | 实际使用的索引 | 为 NULL = 没走索引 |
| rows | 预估扫描行数 | 越小越好 |
| Extra | 附加信息 | `Using filesort`/`Using temporary` 是性能杀手 |

## 九、一句话总结

> 索引是查询加速器：给**高频、区分度高、读多写少**的列建索引；
> 联合索引记住**最左前缀**；慢查询先 `EXPLAIN`，看 `type` 是不是 `ALL`，
> 再查是不是**函数运算 / 隐式转换 / 前置 % 通配符**让索引失效。
